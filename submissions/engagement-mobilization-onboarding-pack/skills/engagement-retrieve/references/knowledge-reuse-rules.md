# Knowledge Reuse Rules
## 1. Closeout adapter
### 1.1 Contract version required
Closeout input must declare `ps.engagement-closeout-knowledge-harvest.v1`.
### 1.2 Knowledge record required
Top-level `knowledge_record` (an object) and `released_assets`, and `knowledge_record.reusable_assets` and `knowledge_record.lessons`, are required lists of objects. An absent member is not an empty list: a missing or null member stops the run with an input error and nothing is written. An explicitly empty list is valid. The closed engagement block (`engagement`) may be absent or null; its records are then unattributed (confidentiality-and-ethical-wall-rules.md #3.3).
### 1.3 Allowed fields only
The adapter reads only `knowledge_record`, `released_assets` and provenance/citations; never `held_assets` or `candidate_assets`.
### 1.4 Types validated, fail closed
Every field the engine reads is type-checked: IDs, titles, descriptions and citations are strings; `tags` and `evidence_citations` are arrays of strings; `knowledge_record.record_id` is a string or null and `evidence_ids` on an asset or lesson is an array (or null) whose items are identifier strings (null or blank items are absent); `review_required`, `rewrite_required` and `review_candidate` are true/false; `confidence` is a number from 0 to 1. A wrong JSON type stops the run with an input error rather than being coerced. Every Closeout identifier (`asset_id`, `cluster_id`, `record_id`, `evidence_ids`, and `engagement_id` and `matter_id` at the record and engagement levels) must have the identifier shape and be a JSON string (confidentiality-and-ethical-wall-rules.md #1.3); prose, spaces or punctuation in one, or a number, true/false, object or array in its place, stops the run with an input error that names the path and does not repeat the value. Flagged Closeout text is withheld (confidentiality-and-ethical-wall-rules.md #4.3). An asset or lesson with a blank or withheld ID joins nothing and is excluded (`not_in_released_assets`, `no_lesson_id`). A missing asset title gets an engine default and a cleared asset with no description gets the fixed statement "No written description is supplied in the governed Closeout record; refer to the title and citation.", never null, so every emitted knowledge item is complete (confidentiality-and-ethical-wall-rules.md #1.3); a pending item's summary is fixed by #2.3. A lesson's `drafting_guidance` is type-checked and screened like every field, but it is never rendered or scored (#2.4).
## 2. Clearance
### 2.1 Released asset required
A reusable asset must also appear in `released_assets` with a release-candidate clearance state.
### 2.2 Confidentiality permission required
Closeout's `released_assets` release-candidate state is the permission for internal engagement reuse. An explicit `confidentiality_permission` other than `cleared_for_internal_engagement_reuse` excludes the item.
### 2.3 Draft not publish
Release candidates remain draft knowledge for practice review. Only an explicit `review_required: false` clears review; true, absent or null items are labelled `pending_practice_review`: reference the title and citation only until Knowledge Management confirms. Review status is derived before any text is chosen, and a pending item never renders its supplied `description` (in the digest, `matched.json`, the pack or the pre-render check): its summary is always the fixed statement "Released Closeout knowledge candidate; use the title and citation only until practice review confirms." A description that is never rendered (a pending item's, or cleared stage guidance under #2.6) is still Closeout text: it is screened for other-client names and read in rendered order beside the knowledge items, with its item's title, ID and citations, as an unwritten lesson's record is (#2.4; confidentiality-and-ethical-wall-rules.md #3.3, #4.5), so a name or split instruction in it holds.
### 2.4 Lessons need a governed rewrite state and written text
A lesson is considered only when `rewrite_required` is explicitly false. Its `drafting_guidance` is an instruction from Closeout to its own drafting step, not lesson content: it is never rendered as a summary or used for relevance, anywhere (digest, `matched.json`, pack or pre-render check). The governed Closeout record (`ps.engagement-closeout-knowledge-harvest.v1`) carries no finished lesson text, so a lesson that clears every other check is not reusable content yet: it is listed in `excluded_items` with reason `lesson_text_not_written_in_governed_closeout_record` and a citation of this section plus the lesson's own evidence citations and citation, and is never a knowledge item. Its record (ID, category, guidance and citations) is still screened for other-client names and read in rendered order after the knowledge items (confidentiality-and-ethical-wall-rules.md #3.3, #4.5), because its citations travel: a name or split instruction in it holds, and the excluded entry's citation carrying any of it is withheld. Source text is never used.
### 2.5 First-week plan never assigns pending knowledge
A SOW first-week item that refers to knowledge content while the digest holds an item whose `review_status` is not `cleared_for_internal_reuse` is treated as directing the joiner to that content, whatever its verb, voice or noun form ("read", "check", "go through", "should be reviewed", "a review of prior knowledge is required", even "do not read the digest yet"), and is not rendered as written. All comparisons are made after NFKC, case and look-alike folding.
- **Exact references first.** Every knowledge ID and full title of every digest item (cleared and pending) is resolved first, longest first, with any separators between their words. An item that names a cleared item exactly, and no pending item, is rendered unchanged; a location word beside it ("from the knowledge digest") is not a pending reference.
- **Title words, pending items only.** In the text not resolved to an exact reference, an item names a pending item by two of its title's distinctive words (words this engagement's own title, client, objectives, scope, exclusions and deliverables do not use), or by one distinctive word and a second title word anywhere in the item. Such a title-word match counts only when the item also carries knowledge context (digest, knowledge, Closeout, lesson(s), reusable asset(s), a previous, prior, earlier or past engagement) or holds every distinctive title word; an item that names a client-owned document or system location ("the client's onboarding checklist", client portal, client system, service portal) without knowledge context is never matched by title words. Beside a cleared item it names, a pending title word that the cleared title lacks ("the onboarding guide and checklist") names the pending sibling.
- **Generic references.** An item that refers to prior knowledge, the knowledge digest, lessons learned or reusable or Closeout assets in general is a reference to every pending digest item. When the digest holds no pending item, nothing is restricted: the item is rendered as written, even if its own wording says "(pending practice review)". No reading verb and no status wording is required: the reference alone counts. People and sessions ("knowledge management lead", "knowledge transfer session") and other digests ("SOW digest", "weekly digest") are not knowledge content.
- **Only administrative items about the review stay.** The one exemption is an item that is clearly administrative about the review itself: every clause is an administrative action (schedule, book, request, chase, confirm, check, ask, follow up, attend, escalate ...) whose object is the review, its status, sign-off or approval, or the practice or knowledge management lead, followed only by plain phrases ("with the practice lead", "for AST-A-001") or by a further such action ("ask the KM lead to confirm the review status"). It is rendered unchanged even when it names a pending item. Any other instruction in the item ("... and read it", "... so you can use it") or an admin verb on the content itself ("Check AST-A-001", "Check the digest") is restated. When in doubt, the item is restated.
- **Adjacent entries are read together.** First-week entries are read in rendered order as the pack's other run screens read lines: runs of 2 to 8 adjacent entries (blank, punctuation-only and withheld entries are skipped and never break a run). A pending ID or title, or a knowledge-content phrase, that only the joined entries spell ("Read AST-A-" / "001 before kickoff") is a reference by every entry in the run, unless the joined run is administrative as above. Every cleared item that any entry of the run names, alone or only in the join, is kept.

A pending reference is restated as a title-and-citation-only note that names each pending item by title and ID, says its content is pending practice review and is not to be read or reused until review confirms, and cites the SOW first-week item number(s) with #2.3 and this section. Cleared items the item names, or, for a generic reference, every cleared digest item, are kept: "read only the cleared item(s) ...". The note never repeats the SOW wording, so it never says both "read" and "do not read" for the same item. In a run, the first entry carries the note for the whole run and each later entry says it continues that item; numbering and every other item are unchanged. When it is uncertain which item is meant, every pending digest item is named. A restatement always names at least one concrete pending item by title and ID; there is no generic pending note.
### 2.6 Stage-addressed guidance is never content
A supplied asset `description` that is guidance to whoever produces the text, rather than written content, is recognised by structure, not by a list of words: (i) it addresses a producer ("For the drafter, ...", "Whoever writes the next version ...", "The next drafting stage should ...", "for the next version", "you should ...", "Preparation note for the next stage: ..."); (ii) it is a directive to produce text: an imperative or a modal construction (should, must, needs to, is to, to be ...) whose verb produces or transforms text (write, draft, summarise, synthesise, condense, rephrase, rewrite ... with any object; create, turn, convert, make, build, prepare, outline, expand ... when the object is text or the verb turns something "into" it), or turns something "into a ... summary, lesson, note or overview"; (iii) it is a placeholder for text not yet written ("to be written", "TBD") or a drafting rule ("Do not quote ...", "from the title and citations only"); or (iv) it is a sentence in imperative mood that names a text product (summary, overview, lesson, note, write-up, narrative, brief, section, draft, paragraph, description, digest) - it opens with a base-form verb followed by its object ("Use the title and citations to create a concise onboarding summary.", "Populate the template with a concise onboarding overview.", "Refer to the cited evidence when writing the onboarding summary."), not with an article, determiner, numeral or pronoun, a noun-phrase head (Checklist, Template, Guide, Summary, Lesson, Playbook ...), a participle ("Used by ...", "Covering ...") or a third-person verb ("Explains ..."). Such a description is not written content. It is never rendered and never scored for relevance (#3.1). A pending item never renders a description anyway (#2.3). A cleared item whose description is such guidance has no finished text, so, as for an unwritten lesson (#2.4), it is listed in `excluded_items` with reason `description_is_stage_guidance_not_written_content` and a citation of this section, and is never a knowledge item. Detection is deterministic and compared after NFKC, case and look-alike folding; factual descriptions, including ones that mention drafters, writers or summaries ("Cleared guide for patient access onboarding.", "Checklist used by the drafting team during onboarding.", "Summary of the governance cadence.", "Onboarding guide written by the delivery team.", "Used by the delivery team to prepare weekly summaries."), render unchanged; an "into a ... summary" phrase inside a relative clause of a noun phrase ("Template that turns raw notes into a status summary.") describes the asset and is not guidance. When a description is ambiguous, it is treated as guidance (fail toward caution).
## 3. Matching
### 3.1 Relevance is deterministic
Relevance is computed from token overlap between the engagement scope and an item's narrative only (title, description, tags and category); a description that is stage-addressed guidance (#2.6) contributes nothing. IDs, citations, scores, confidence and other metadata never contribute terms or numbers, so an asset ID built from this engagement's words does not make it relevant.
### 3.2 Sources travel with digest
Every item carries source, confidence, provenance and citations.
