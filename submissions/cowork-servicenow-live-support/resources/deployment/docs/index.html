ServiceNow live support inside Copilot Cowork

Sanitized library-review source package, not an installed or certified service. Historical tenant reports, identities, deployment endpoints and recordings are omitted. Read README.md, CONFIGURATION.txt and RELEASE-CHECKLIST.txt first.

1. Architecture and isolation

Cowork calls the .NET MCP bridge using Streamable HTTP at /mcp. The model-visible start_live_chat tool creates only a local, owner-bound draft and renders the MCP App widget. The employee reviews the request in the panel and selects Request support before the bridge sends it to ServiceNow.

Cowork → MCP App widget → .NET MCP bridge → ServiceNow REST
ServiceNow callbacks → authenticated .NET endpoint → SQLite events → widget polling

The panel owns its own message input and transcript. Human messages are brokered through app-only MCP tools, not sent through the model or the main Cowork composer. The panel cannot intercept, lock or take over the host composer. App-only visibility is enforced by a compatible host, not an independent authorization boundary.

The request-first layout keeps the approved request visible above employee and representative messages. Details contains reference numbers and service history; errors and uncertain delivery remain visible. Explicit button handlers and Enter-to-send avoid native form submission because the host iframe sandbox may omit allow-forms.

This is separate from the standard-harness .NET skill: no Agents SDK activities, Copilot Studio skill registration or existing Teams return path is reused. ServiceNow uses its own cowork_bridge API, cowork_bridge.* settings, u_cowork_session_id, u_cowork_upn and cowork_mcp marker.

The widget refreshes active chats every four seconds and closed remote sessions every fifteen seconds while visible; hidden panels pause. These are polling updates, not server push. Recheck current host quotas before deployment.

3. Identity and data boundaries

Cowork uses an independently registered delegated OAuth client and the LiveChat.Access scope. Validate v2 issuer, tenant, audience, signature, expiry, scope and owner identity. Choose a signed email claim and allowed domains that resolve to exactly one active ServiceNow user. The token-store OAuth reference is neither a secret nor the Entra application ID.

The bridge has independent ServiceNow client credentials. Callback tokens use a distinct audience, a dedicated application caller allowlist and LiveChat.Webhook role; delegated callback tokens are rejected. Callbacks arrive at /api/livechat/sn. The iframe receives no credentials. No Basic or shared-secret authentication fallback is supplied.

Only the reviewed summary and typed messages should be shared, never the full host conversation, private files or hidden context. Render human text as untrusted data. Optional translation must be explicitly approved, labeled and retain original text; it introduces another processor and is disabled by default.

4. ServiceNow installation

Read ServiceNow deployment and installer safeguards. The supplied target example.invalid, namespace cowork_review and zero legacy pins are nondeployable templates. Adapt the client, definition, strict generator guards and associated tests together after independent target review; do not remove guard checks to make an existing installation pass.

Create separate OAuth applications, runtime account, queue/channel, callback provider, properties, fields, tables, ACLs, idempotency ledger and outbox. Check collisions, plugin/license availability, schema, real unique indexes, lease concurrency and minimum roles before activation. Do not grant admin or security_admin to the runtime identity. The installer is create-only, dry-run by default and not an upgrader.

Inspect any existing fanout rule separately. Only a specifically reviewed exclusion for Cowork-tagged sessions may be appropriate. Preserve unrelated harnesses, routing and credentials. The offline legacy helper emits review proposals only and is blocked until a target rule is pinned; it never writes to ServiceNow.

Keep cowork_bridge.enabled and cowork_bridge.outbox_delivery_enabled false during staging. Verify callback authentication, retries, dead-letter monitoring, restrictive ACLs and dedicated schedule run-as before delivery; enable new handovers last. No deployment approval is implied.

6. Operations, recovery and acceptance

Use exactly one host process and a persistent local SQLite volume, never shared network storage or horizontally shared replicas. Protect transcripts and backups with OS ACLs, encryption and approved retention. Terminal retention defaults to seven days; active and ambiguous operations remain retained.

Commit session and operation keys before network I/O; acknowledge callbacks only after commit. Preserve IDs on retry. Ambiguous open/send operations are not blindly replayed; reconcile in ServiceNow. Only eligible close operations retry with a stable key; HTTP 409 pauses uncertain closure. Late replies remain visible without reopening terminal sessions. Closing the panel does not close the support conversation.

Before real use, independently test consent, wrong-owner/tenant/audience/caller rejection, one interaction per request, two-way agent-console messages, duplicate commands/events, restart, remount, delays, timeouts, closure, dead letters and rollback. Confirm no callbacks reach unrelated harnesses. Local mocks do not prove these platform behaviors.

7. Support and licensing limitations

The scripts use internal, release-sensitive ServiceNow APIs including sn_cs.VASystemObject.createConversation, sn_cs.AgentChatScriptObject.send, chat session bindings and AWA writes. API exceptions can be ambiguous after persistence; do not blindly repeat sends. Obtain target-release validation or adapt to documented APIs. This sample supplies no vendor support, SLA, certification, internal-API rights or production-readiness claim.

Scope is text chat, not attachments, voice, typing indicators or automatic host-composer handoff. Host MCP Apps/OAuth availability, iframe policy, current quotas, accessibility and runtime support require review. This new gallery contribution adopts the supplied gallery-root MIT LICENSE. Dependencies retain their own licenses/notices; platform entitlements are not included. Publication and target deployment require separate approval.
