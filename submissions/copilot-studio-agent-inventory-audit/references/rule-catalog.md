# Rule catalog

Each rule the script evaluates: what triggers it, how severity is set, why it matters, what the inventory cannot prove, and where the fix lives. Severity is a review heuristic for ordering work. It is not a Microsoft rating and not a compliance verdict. A rule runs only when the file the audited agents come from carries the fields it needs and the export populates them somewhere; the report lists the rules it skipped and why ("not in export", "not in the file the audited agents come from", or "present but empty in every record"). LC1 and OW2 are the exceptions: their evidence is an empty value, so they need only the column to exist. When files from different routes are combined, each rule runs only on the agents whose own file carries its fields; the header lists the rules that skipped part of the scope and why. When an export is a truncated API page, the header says so and tenant-wide statements are not supported.

Severity scale: **high** means exposure or loss of control to confirm this week; **medium** means a control gap to schedule; **low** means hygiene; **info** means a fact to know, not a defect.

Rules are evaluated per agent except CR3 (per shared connection, naming every agent that uses it) and OW3 (per owner). Those two appear in the findings and remediation with their agent lists; CR3 also counts toward each named agent in the attention and environment tables, OW3 does not.

## Identity

Agent 365 and Entra governance attach to an agent's Microsoft Entra Agent ID, so ID1 and ID2 agents are not yet governable that way; Agent Builder agents are governed through Microsoft 365 Copilot settings. The inventory cannot show whether Agent 365 is enabled.

**ID1 No agent identity recorded.** Published Copilot Studio agent (not Agent Builder) with no `entraAgentId`, `entraAppId`, or blueprint ID. High when the export carries populated Entra Agent ID and app registration columns. Medium when either column is absent or empty in every record, because the agent may hold an identity the export cannot show; the detail names the missing column. Agent Builder agents are excluded (no identity by design); drafts are excluded (GitHub Copilot harness agents receive their identity at first publish). *Why:* without an identity there is nothing for Entra audit logs, lifecycle governance, or Conditional Access to attach to. *Verify:* Copilot Studio Settings > Advanced > Metadata shows the Entra Agent ID or application ID; the Microsoft Entra admin center lists it under Entra ID > Agents > Agent identities. *Fix:* republish; if still absent, open a support request.

**ID2 Legacy app registration identity.** `entraAppId` present and `entraAgentId` empty. Medium. When the export has no populated Entra Agent ID column at all, the finding still lists the agent (so the migration list is complete) but says the agent may already be migrated and asks for confirmation in Settings > Advanced > Metadata. *Why:* governance works for both identity types during the transition, but connector scopes as API permissions, and Conditional Access on those scopes, exist only on Entra Agent IDs. Application, Cloud Application, and Global administrators can add credentials to an app registration; nobody in the tenant can mint tokens for an Entra Agent ID. *Fix:* migrate in the Power Platform admin center (Actions > Recommendations), with PowerShell, or through the migration API; manual migration is in preview and reversible, keeps the agent's GUIDs, and Microsoft is also migrating remaining agents automatically.

## Exposure

**EX1 Published without user authentication.** `authentication` is None, the agent is published, and at least one channel is listed. High when any channel is outside Teams and Microsoft 365 Copilot (custom website, demo website, SharePoint, telephony, third-party), because anyone with the link can chat. Medium when only Teams or Microsoft 365 Copilot channels are listed: Microsoft documents that channel as requiring Authenticate with Microsoft and blocked otherwise, so the combination is usually stale channel data or a legacy configuration to confirm on the agent's Channels page. The detail notes maker-provided connections and tenant-wide sharing when present. *Why:* an agent with no user authentication cannot trim knowledge or tool results to the user, and any tool on a maker-provided connection runs for anyone who reaches it. *Verify:* whether the channel is really reachable (a custom website channel with no site embedding it is exposure in waiting; the demo website is a Microsoft-hosted page reachable by anyone with the link), and whether anonymous access is intentional, for example a public FAQ. *Fix:* Copilot Studio Settings > Security > Authentication, then republish; or remove the channel. A data policy can also require authentication for an environment.

**EX2 Shared with the entire tenant.** `sharedWithViewers.entireTenant` true. Medium; high when combined with no authentication, maker connections, or web search. *Why:* tenant-wide availability multiplies every other finding on the agent. The flag records the maker's choice, not an approval. *Verify:* which path was used. Copilot Studio Share > Everyone in the organization has no approval step: every licensed user can chat once the agent is published. A store submission (Show to everyone in my org > Submit for admin approval) waits in Microsoft 365 admin center > Agents > All agents > Requests (states Pending review, Pending update, Pending activate) or in the Teams admin center. *Fix:* narrow viewers to named groups or accept and document the sharing. To limit how broadly makers can share in future, use Managed Environments sharing limits for Copilot Studio agents and Microsoft 365 admin center Copilot settings (All users, Specific users or groups, No users) for Agent Builder agents. On a never-published draft the finding is advance notice: review before first publish.

**EX3 Web search enabled as knowledge.** `isWebSearchEnabledForKnowledge` true on a published agent. Medium. *Why:* answers can come from the public web and carry its content and links to users who expect organizational answers. *Verify:* whether that is acceptable for the audience, and the environment's content-safety settings for images and embedded URLs (Power Platform admin center > Security > Threat detection, or environment group rules). *Fix:* turn web search off on the agent, or confirm the audience and keep it; a data policy can block public-web knowledge where it is never acceptable.

**EX4 Broad editor access.** `sharedWithEditors` has any group, or at least the editor threshold of individual users (default 5). Low. *Why:* every editor can change instructions, tools, and knowledge and republish. *Verify:* who is in the groups. *Fix:* reduce to the maintaining team.

## Credentials

**CR1 Maker-provided connection used for tools without end-user consent.** On a published agent, an enabled operation used as Tool or Topic Tool where `connectionProvider` is Maker, `requiresEndUserConsent` is explicitly false, and `whenCanBeUsed` is Anytime or absent from the export (the detail says which). An operation whose consent value is missing from the export is not assessed: the finding (if any) and a warning count those operations as unknown rather than treating them as no-consent. Medium; high when the agent has no user authentication or is shared with the entire tenant. Drafts are left to LC1, which names their parked maker-provided connections. *Why:* the operation runs with the maker's permissions for every user, the orchestrator may call it whenever it judges fit, and the user is never asked. When ordering actions, lead with write operations (send mail, add rows, run scripts, create records). *Verify:* the maker's permissions in the target system and whether the operation writes. *Fix:* switch to a user-provided connection, enable end-user consent, restrict `whenCanBeUsed` to direct reference, or document the operation as a deliberate service action with an owner.

**CR2 Maker-provided connection used for knowledge.** `usedAs` Knowledge with `connectionProvider` Maker on a published agent. Medium. *Why:* results are limited only by what the maker's connection can see, not by the asking user's permissions. *Verify:* whether the source holds data with varying permissions. *Fix:* user-provided connection, or restrict the agent audience to people entitled to the full source.

**CR3 Maker-provided connection reused across agents.** The same `connectionIdSharedByMaker` appears in two or more agents. Medium, reported once per connection with the agents listed; the report's shared-connections table also lists single-agent maker connections. *Why:* one credential is the blast radius of several agents; rotating or revoking it, or removing its owner's account, stops all of them. *Verify:* who owns the connection (Power Platform admin center > Environments > the environment > Connections) and whether it is a service account. *Fix:* document the connection, prefer one connection per agent for high-impact connectors, move to service identities where supported.

**CR4 Custom or watched connector in use.** Connector ID matches the `--watch-connectors` list (medium) or looks like a custom connector (low; a heuristic on the ID shape, see the field catalog). The watch list, or a lookup against the tenant's connector records, is the authoritative test. *Why:* custom connectors, MCP servers, and REST tools do not add API permissions to the Entra Agent ID, so Conditional Access on the identity never sees them; only connector and data policies govern them. Watched connectors are whatever the organization considers sensitive. *Fix:* policy review.

**CR5 Disabled connector operations left configured.** Operations with `isEnabled` false. Low. *Fix:* remove them.

## Lifecycle

**LC1 Draft never published.** `lastPublishedAt` empty and `createdAt` older than `--draft-days` (default 90). Runs whenever the `lastPublishedAt` column exists, even if it is empty for every agent (an all-draft export). Low; medium when the draft holds maker connections, which the detail names as a parked credential rather than runtime exposure. *Verify:* with the owner. *Fix:* publish, delete, or justify.

**LC2 Quarantined or blocked.** `isQuarantined` true. Medium. *Why:* a quarantine is an investigation nobody has closed. Makers can still test the agent; nobody can use it in a channel. *Fix:* finish the investigation; release through the Power Platform admin center or the quarantine API (Global, AI, or Power Platform administrator), or delete.

**LC3 Unmanaged agent in a Production environment.** `isManaged` false, environment type Production, published, not Agent Builder. Medium. Needs environment type from a join or joined columns. *Why:* changes happen directly in production outside any deployment pipeline. *Fix:* managed solutions and pipelines; restrict direct editing in production.

**LC4 Published from the Default environment.** Environment type Default, published, not Agent Builder (those live in Default by design). Low; medium when also shared with the entire tenant, without user authentication, or running tools on maker-provided connections. *Why:* every licensed user holds the Environment Maker role in Default, and the environment cannot be deleted or reset, cannot be manually backed up, and a backup cannot be restored over it. *Fix:* move shared agents to a governed environment; use Managed Environments, sharing limits, and environment routing to keep new work out of Default.

**LC5 Published from a Developer or Trial environment.** Environment type Developer or Trial, published, with channels listed. Low. *Why:* developer environments are for their owner and trial environments expire. *Fix:* move.

**LC6 Inventory truncated at 200 resources.** Any `capabilitiesCounts` value above 200. Info. *Why:* the connector list in the export is a random subset, so credential rules may have missed operations. *Fix:* review the agent's tools in Copilot Studio directly.

**LC7 Not republished for a long time.** `lastPublishedAt` older than `--stale-days` (default 365). Info. *Verify:* usage in Copilot Studio analytics. *Fix:* refresh or retire.

## Ownership

**OW1 Owner account disabled or departing.** Owner matches `--departing` (object ID, or UPN when a user list maps it) or is marked disabled, departed, or inactive in the `--users` file. High. Not evaluated unless a departing list or a user list with account state is supplied; when some owners are missing from the user list, a warning counts them as unknown rather than treating them as active. *Why:* when the account goes, the agent is orphaned and the maker connections it uses stop working. *Fix:* reassign ownership with the Power Platform API reassign operation or PowerShell (Global, AI, Power Platform, or Environment administrator), or in Microsoft 365 admin center Agents for shared agents; the previous owner loses access and the new owner re-creates maker-provided connections. The owner-handover mode (`--owner`) lists everything that depends on one person.

**OW2 No owner recorded.** `ownerId` empty on a published agent whose record carries the column. Medium. Runs even when every record has an empty owner; the detail then asks you to confirm that the export route carries owners before treating the agents as orphaned. *Fix:* assign an owner the same way.

**OW3 Ownership concentration.** One owner holds at least `--owner-threshold` agents (default 15). Low, reported once per owner. *Why:* key-person risk. *Fix:* co-owners, documented transfer path, service accounts for platform-owned agents.

## Region and model

**RG1 Outside allowed regions.** `location` not in `--allowed-regions`. Medium. Not evaluated unless the list is supplied. *Fix:* confirm the region or re-create the agent in an approved environment.

**MD1 Non-Microsoft model as primary model.** Model name contains `claude`, `anthropic`, `sonnet`, `opus`, `haiku`, `mistral`, `grok`, `llama`, `gemini`, `deepseek`, `cohere`, or `command-r` (Microsoft currently offers Anthropic, Mistral, and xAI models as primary models; the others are included in case they appear). Info. *Why:* Microsoft notes that some models may process and store data outside the organization's geographic boundary. The same cross-geo note applies to several GPT models outside the US, Europe, and the UK, so a model name alone does not establish where data is processed. *Verify:* the model's data processing terms against the agent's data classification. *Fix:* switch models where the classification does not allow it.

## What no rule can see

The inventory is a catalog of published configuration; the field catalog's "Limits of the inventory" lists what it never contains (instructions, knowledge content, usage, data policy results, Conditional Access state, Entra sponsors, Copilot Credits, evaluation results, whether Agent 365 is enabled). Say so whenever a reader could mistake a clean audit for a safe estate.
