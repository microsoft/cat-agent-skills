# Work IQ sphere: errors in plain English (skill version 2.0.0)

Read this whenever a script or tool prints an error, warning or note, or a tool call fails (SKILL.md, Part F). Say the middle column to the person, then do the last column. Never show them the raw error.

| The script or tool says | Tell the person | Then |
|---|---|---|
| A file the skill needs is missing (the completeness check in SKILL.md fails, or `No such file or directory` / `can't open file` for a path inside `<skill>`) | Your Work IQ sphere skill is only partly installed, so I've stopped before reading any of your data. It needs the whole work-iq-sphere skill, not just SKILL.md. To fix it, add it again in one of two ways: in Copilot Cowork, go to Customize > Skills > Upload skill and choose the work-iq-sphere.zip file (don't attach the zip here); or extract the zip on your PC (right-click it, then Extract All), delete the work-iq-sphere folder in OneDrive under Documents > Cowork > skills, and drag the whole work-iq-sphere folder into skills. Either way it shows SKILL.md plus four folders: examples, references, scripts and templates. When it has finished uploading or syncing, start a new conversation and ask me again. | Stop. Read no more data, deliver nothing, and never recreate the missing files. |
| GetMyDetails fails or gives no UPN | "I couldn't confirm who is signed in, so I can't build your sphere yet. Please try again in a moment." | Stop. Never guess the person or take a name from the chat. |
| `no mail or calendar rows fall inside the window` (the three-month run) | "I couldn't find mail or calendar items for those dates, so I'm checking the dates and reading them again." | Check start, weeks and result paths; redo steps 2 and 3. |
| `no mail or calendar rows fall inside the window` (a week or month run) | Only in the reply, under "Left out": "The <Week or Month> view is left out: there was no mail or calendar activity in <the last 7 days or the last month>." | Leave that view out: no step 8 run and no `--view` for it in step 10. |
| Sent Items show a legacy X500 sender (`/O=EXCHANGELABS/...`) instead of the person's address | Nothing to say. | Handled automatically: the scripts count those Sent Items rows as sent by the first `--self` address (only in Sent Items). Never edit the result files or pass the X500 address as `--self`. |
| A personal webmail domain (outlook.com, gmail.com and the like) in the mail | Nothing to say. | Handled automatically: those senders are personal contacts, never organisations, so they are not `org:` items and the customer-safe checks ignore them. |
| `Sent Items were sent from`, `sent none of the mail in your Sent Items`, `the fictional sample person` or `come from the bundled fictional sample` | "Some of the files I read weren't your own mailbox, so the skill stopped. I'm reading your data again." | Redo steps 2 to 4 for the signed-in user only; `--self` as in A1; never pass the sample's data. |
| The files tool script fails or is refused, `could not read /me/drive/recent`, or Graph refuses calls (a failure limit in this conversation) | "Your OneDrive and SharePoint files couldn't be read this time, so this sphere is built from your mail, calendar and chats." | Build without files: no `--files` anywhere, no Files row, the reason under "Left out". Never retry a failing call in a loop. |
| `does not say whose files it lists`, `lists the files of`, `was collected for ... as well` or `files come from the bundled fictional sample` | "The files list wasn't stamped as yours, so I'm collecting it again from your own account." | Run step 5 again; if it fails, build without files as above. |
| `keywords ... are copied from a bundled sample`, `matches empty text`, `too short to mean anything` or `says nothing about one customer or theme` | "Some topic words I picked weren't specific to your work, so the skill stopped me. I'm rewriting them from your own data." | Rewrite keywords.json from discovery terms (products under `p_`); redo every run of step 8. |
| `this config was not made by a fresh analysis` or `the saved config ... was made for` | "The setup I was about to use wasn't made from your data with this version, so I'm building fresh from your own data." | New build. Never patch `meta`. |
| `were counted for`, `discovery.json was made for`, `different --self addresses`, `come from different data`, `cover different windows`, `columns in "weeks"`, `files and the signals`, `signals.files ... is not what discover.py found` | "Two parts of the analysis didn't match (different data, dates, files or person), so the skill stopped. I'm redoing them from exactly the same data of yours." | Redo steps 6 and 8 with identical `--messages`, `--calendar`, `--folders`, `--chats-file`, `--files`, window flags and `--self`; copy `signals` and `weeks` from the new three-month signals.json. |
| `you chose the window`, `does not say which window you chose`, `is not a window this skill knows` or `the week and month views go with a three-month sphere` | "The dates I analysed didn't match your three-month window, so I'm redoing them for it." | Run window.py with `--views`, set `meta.choices.window` to `"quarter"`, redo steps 6 to 10 with `views.quarter.flags` for the config and each view's own flags for its runs. |
| `do not record the same collected data (meta.source)` | "Two parts of the analysis came from different reads of your data, so I'm redoing them from the same one." | Redo every run of steps 6 and 8 with this version's scripts on the same result files. |
| `view was made for`, `view was made on`, `view must be counted`, `comes from different data than the three-month run`, `was not made with --view-of`, `was not counted with --view-of`, `view signals.json is not exactly what count_signals.py wrote`, `count different emails or calendar events`, `chats, but its discovery.json found`, `columns are not the`, `files but the three-month run`, `is not the three-month run of this same data` or `is not the three-month count of this same data` | "The Week or Month view didn't match your three-month data, so I'm redoing it from exactly the same data." | Redo that view's runs in steps 6 and 8 on the same day with exactly the three-month runs' arguments, its own `flags` from step 1 and `--view-of`; never edit the view files. |
| `was counted with other keywords than the three-month run` or `was counted for another focus than the three-month run` | "The Week or Month view was counted with different topic words, so I'm counting it again." | Redo the week and month runs of step 8 with the same `--keywords` and focus flags as the three-month run. |
| `--view takes week or month`, `view was given twice`, `cannot read the ... view` or `--view-of ... is not a discovery.json` or `is not a signals.json` | "I made a small consistency mistake in the setup. Fixing it." | Pass `--view week` and `--view month` once each, with the files steps 6 and 8 wrote, and `--view-of` with the three-month files. |
| `the "signals" block is not exactly what count_signals.py wrote`, `signals count`, `signals.chats is` or `the config weeks` | "A number in the setup didn't match what was counted, so I'm putting the counted numbers back." | Paste the whole three-month signals.json from step 8 unchanged, with its `weeks`. |
| `not in your discovery.json`, `no evidence from your own data` or `people need "person:" evidence` | "A few items had no evidence in your own data, so the skill held them back. I'm linking them to the right evidence or removing them." | Cite exact ids from the three-month discovery.json or remove the item; `stated:` only for what the person said (A4). |
| `these names do not match the evidence they cite` | "A few names didn't match the items they point to, so I'm renaming them from your own subjects." | Rename the node with the words its evidence shows (add `aka` for a translation), cite the right item, or remove it. |
| `only files you edited or created are evidence`, `a site is evidence only when you edited at least 2 files there` or `"site:" items are evidence only for` | "One item pointed at a file or site that doesn't show your own work, so I'm linking it to the right evidence." | Cite a file the user edited, a site with at least 2 of their files, or other evidence; themes, products, people and escalations never cite files or sites. |
| `these "stated:" or "source:" items cannot be used` | "One item rested only on what was said, in a way the skill doesn't allow, so I'm checking it with you." | `stated:` only for programmes, themes, products, assets and outputs, in the person's words naming the item, at most 3 nodes and 2 outputs; `source:` only on internal items. |
| `meta.choices.focus names`, `is not in your own discovery: a focus` or `but you chose a ... focus` (the focus entity) | "The focus you named wasn't set up right on your sphere, so I'm setting it up again from your own data." | Make the focus entity from focus.py's `name` and `evidence`, with the chosen class and the focus `id`; if focus.py says `not_found`, build for all their work (never ask). |
| `your numbers are for`, `your numbers cover all your work`, `signals.focus`, `the focus pattern`, `a customer focus needs --focus-domains` or `only a customer focus has domains` | "Your numbers weren't counted for the focus you named, so I'm counting them again for it." | Run focus.py again, then every run of step 8 with exactly its `flags`; paste the whole three-month signals.json. |
| `shows no other customer` or `leaves other organisations off` | "A sphere about one customer shows only that customer, so I'm taking the others off." | Remove the listed items. |
| `do not connect to the focus` or `nothing in your own data connects these to the focus` | "A few items weren't about your focus in your own data, so I'm linking them properly or leaving them out." | Link each to the focus, or to something linked to it, with a relationship the data supports (not through `me`), or cite evidence that names the focus or involves its domains; otherwise remove it. |
| `must name the focus with its token` | "The title didn't name your focus, so I'm adding it." | Put `{<focus id>}` in `text.headline` (and in `text.slideTitle` if set). |
| `Skills questions` or `Skills question ...` | "One of the Copilot questions wasn't specific enough to your work. I'm rewriting it." | Four different `kind`s, each with `from` items of that kind, `{tokens}`, highlight ids and a grounding line with counts (placeholders); with a focus, each names it with its token or highlights it. |
| `these numbers are not in your own counts` or `these dates are outside your own window` | "A number or date in the text didn't come from your own counts, so I'm recomputing it." | Recompute it with code from signals.json and discovery.json, or remove it. |
| `are typed in, so a three-month number would reach the week` or `fall outside the last 7 days` | "A number or date in the text would have shown the same in every view, so I'm writing it so each view fills in its own." | Write each count in text every view shows as a placeholder (step 9), a date as `{#<item id>.last}` or `{#signal:<key>.peak}`, a period as `{#period}`; or leave it out. Rebuild. |

| `the sphere must be about you` or `these names are not backed by your own data` | "A title or label named something that isn't in your data, so I'm rewording it." | Owner, title and source name only the user; lane names describe their keyword; portals are Microsoft experiences or the user's own agents. |
