# Severity Rules - Deliverable Review & Quality Gate
Deterministic rules consumed by assertion_map.py, gate_check.py and severity_rank.py. Constants in the engines mirror these sections.

## 1. Severity classes
1.1 `release_blocker`: issue creates firm-risk, client-risk or third-party reliance risk if the deliverable is released as-is. Examples: unsupported headline quantified benefit, wrong reliance language for a third-party recipient, confidentiality breach, or an unsubstantiated conclusion framed as definitive.
1.2 `must_fix`: issue must be corrected before release but does not alone create the same immediate release-risk profile. Examples: missing licensed-content attribution, prior finding marked closed without the fix, required limitation missing near a recommendation.
1.3 `advisory`: quality, clarity or formatting improvement that should be reviewed but does not block partner judgement or release by itself.

## 2. Confidence floors
2.1 Any extraction, mapping or gate confidence below 0.72 is escalated for human confirmation.
2.2 Evidence support below 0.70 is treated as unsupported unless a stricter assertion-class floor applies.
2.3 Quantified claims require evidence support at or above 0.80 and traceable analytical provenance.

## 3. Ranking and downgrade controls
3.1 A release blocker can never be auto-downgraded by the model, by narrative polish, by schedule pressure or by the existence of a disclaimer.
3.2 Findings rank first by severity, then by confidence, then by page and paragraph so a reviewing partner starts with the highest-risk issue. `location.page` and `location.paragraph` must be integers or null; null (a register-level finding with no page) ranks after page-located findings of the same severity and confidence. Printed page labels such as roman numerals belong in `location.label`; any other page or paragraph value is a clean input error, never a guessed order.
3.3 The review-status verdict is `not_ready_for_release` if any release blocker exists, `partner_review_required_must_fix` if must-fix items exist without blockers, `partner_review_required_advisories_only` when only advisories remain and `partner_review_required_no_engine_findings` only when no findings and no escalations exist. Escalations with no finding give `not_ready_for_release`. When findings exist, the verdict follows the highest finding severity, and each escalation still needs partner/QRM confirmation before release; the verdict summary states the escalation count, so it never reads as findings alone. `findings` and `escalations` are required arrays; an absent or non-array value is a clean input error, never an empty run.
3.4 One finding is kept per `finding_id`. Findings that share an ID (exactly or after folding) but differ in any field are malformed input, refused at every stage with no output, so one can never mask or downgrade another (quality-gate-criteria.md #8.11), except that a differing copy of an engine-owned finding is replaced by the genuine one and held as a spoof (#3.8). Identical copies are collapsed to one, so a duplicate is never counted twice, and the collapse is escalated for confirmation.
3.5 severity_rank never trusts gate_check output it did not compute. It validates the whole input against the contract (required fields, JSON types, closed enums such as `gate_id` G1-G8, and provenance prefixes) and reconciles `gate_results` with `findings[]`: there must be exactly one entry per gate G1-G8, and each entry's `status`, `highest_severity` and `finding_count` must equal what the findings give. Any violation or mismatch is a clean input error with no output, so a gate reported blocked can never reach a lower verdict because its findings were removed or downgraded; re-run gate_check instead. After forged findings are removed, G8 holds added and duplicates collapsed (#3.4, #3.6, #3.8), severity_rank recomputes every gate result's `status`, `highest_severity` and `finding_count` from the final findings, so its own output always passes this check on a re-run.
3.6 severity_rank screens every incoming string and member name, and every pair of adjacent array entries, through the same `steering_guard` call gate_check uses (quality-gate-criteria.md #8.5-#8.7). A primary-field hit gate_check already holds under its own G8 finding is not counted twice; that is judged only against the findings and escalations gate_check re-derives (#3.7), never carried copies, so a pasted G8 history hold or overflow note cannot silence a hit (quality-gate-criteria.md #8.16). A hit is already held only when gate_check's re-derived screen holds that exact path, listed or counted in its overflow note, never because gate_check listed its maximum number of holds (quality-gate-criteria.md #8.19). Any other hit, including text in findings, escalations, gate results, provenance or assertion mappings, is withheld from the output and raises an `SR-G8-embedded-instruction-N` release blocker (up to five, then an overflow escalation) plus an escalation; the G8 gate result is updated to match. Every withheld placeholder outside the sections severity_rank recomputes must be bound to a G8 hold naming its exact field path (a re-derived gate_check G8 finding or a carried G8 history hold); an unbound placeholder raises its own `SR-G8-embedded-instruction-N` hold, and a hold naming another path never binds it (quality-gate-criteria.md #8.18). After ranking, the rows the review packet renders (ranked findings, unsupported or limited mappings, escalations) are screened pair by pair across adjacent fields and consecutive rows, then as one sequence in sliding windows and whole, as read and as the template renders it (quality-gate-criteria.md #8.22); gate_check has already withheld any such text, so a ranked output in which any of these still trips, or whose rendered packet is too long to screen whole, is a clean input error with no output, at a run and at `--verify`.
3.7 severity_rank re-derives the engine findings instead of trusting them. gate-checked.json carries the mapped input (the primary sections, top-level fields and `assertion_mappings`), so severity_rank re-runs the gate_check engine on it with the same functions, passing back only the `AM-` findings (gate_check verifies them against assertion_map) and no escalations. Every finding gate_check derives must be present in `findings[]` under the same `finding_id` and gate at no lower severity. Carried copies are matched to each derived finding on the canonical ID alone, never selected by a field the input can edit, and then compared: with no copy under the exact engine ID it is missing (a respelled or one-character-edited ID counts as missing), with copies only under another gate it is re-gated, and with copies only at a lower severity it is downgraded (quality-gate-criteria.md #8.20). Every escalation it derives must be present in `escalations[]` unchanged, compared as a multiset of exact entries, and `gate_results` must list the gates in gate_check's order with exactly its members, each entry's `name`, `confidence`, `source` and `citation` equal to gate_check's own (quality-gate-criteria.md #8.19), so deleting or softening an escalation or relabelling a gate is refused the same way (quality-gate-criteria.md #8.16). A missing, downgraded or re-gated engine finding, or an edit to the carried mapped input that changes what gate_check derives, is a clean input error with no output, even when `gate_results` were edited to match (#3.5); re-run assertion_map and gate_check instead. Upstream or extra findings, escalations and provenance may only add: they rank normally and their text is screened (#3.6); engine-owned findings are held to #3.8. These checks run first; the gate-checked input must then equal its whole-document re-derivation from the review input (quality-gate-criteria.md #8.21), so at the command line any edit to an intermediate, including an added finding, escalation or provenance entry, is refused after them.
3.8 Engine-owned findings must be exactly what re-derivation produces. A supplied finding with an engine-owned ID prefix (`AM-`, `GC-` or `SR-`, in any case) or an `engine:` source tag stands only when gate_check re-derivation produces the identical finding (same ID and every field equal), or, for an ID re-derivation does not produce, when it is a G8 history hold (`GC-G8-engine-id-spoof`, `GC-G8-embedded-instruction-N`, `SR-G8-engine-id-spoof` or `SR-G8-embedded-instruction-N`, where N is 1 to 5, the most G8 hits an engine lists) equal in every field to the hold its own engine builds for the counts or field path its detail names, which can only hold the run. A finding under a derived ID is always compared with the derived finding, never accepted as a history hold, and editing only its `source` never takes it out of the comparison (quality-gate-criteria.md #8.20). Any other engine-owned finding, whether extra or an edited copy of a derived one, is removed after its text is screened (#3.6), with ownership read from the raw ID and source tag in canonical form before screening, so a withheld engine ID is still removed; the derived finding is restored in its place, and an `SR-G8-engine-id-spoof` release blocker and an escalation are added. A differing copy of a derived finding (same ID exactly or after folding) is removed the same way, the genuine finding is kept once, and the copy is never refused as a duplicate. A forged `AM-` finding that collides with no derived finding is already spoofed by gate_check re-derivation, so its GC hold is missing and the input is refused under #3.7. Every engine is idempotent: run again on its own output with the same `--generated-at` and review input, it reproduces that output byte for byte, and escalations and provenance engine tags it already carries are not repeated. The removals and holds above are defence in depth inside the stage; at the command line the whole-document re-derivation (quality-gate-criteria.md #8.21) refuses an edited engine-owned finding before any output is written.

## 4. Human judgement boundary
4.1 The engine can block or flag; only the reviewing partner or authorized QRM role can clear the gate.
4.2 The review packet must state that it does not approve release, sign off the deliverable, clear the quality gate or substitute for professional judgement.
