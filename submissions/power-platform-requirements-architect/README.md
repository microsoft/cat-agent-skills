# Power Platform Requirements Architect

Turn a Power Platform solution idea into a complete, traceable requirements baseline that a separate coding agent can implement without access to the discovery conversation.

## What this skill does

The skill acts as a senior Power Platform requirements engineer and solution architect. It conducts a structured stakeholder interview, resolves material business and architecture decisions, and produces one canonical YAML handoff.

It covers:

- business outcomes, actors, scope, journeys, exceptions, volumes, and nonfunctional requirements;
- Power Apps, Dataverse, Power Automate, Power Pages, integrations, and Copilot Studio architecture where relevant;
- security, governance, environment strategy, ownership, and deployment inputs;
- traceable requirements, acceptance criteria, work items, dependencies, human gates, and build order;
- explicit approval and a separate coding-agent readiness decision.

## When to use it

Use this skill before implementation when a business process, app idea, automation, Dataverse solution, Power Pages site, integration, or Copilot Studio agent needs to be understood and specified.

Typical requests include:

- "Help me define the requirements for a Power App."
- "Turn this process description into a build-ready specification."
- "Interview the stakeholders and prepare a handoff for a coding agent."
- "Design the requirements and architecture for this Power Platform solution."

## Deliverable

The only machine-readable deliverable is one complete `POWER_PLATFORM_SOLUTION_SPEC_V1` YAML document. It contains the approved baseline and the coding-agent execution contract in a single artifact.

The skill keeps two decisions separate:

- **Requirements approved** means the business and architecture baseline is complete and explicitly approved.
- **Coding-agent ready** means all required deployment inputs, authority boundaries, target environment rules, and stop conditions permit implementation to begin.

An approved specification can therefore remain blocked when tenant-owned information or governance decisions are still missing.

## Workflow

1. Classify the expected solution complexity.
2. Interview stakeholders in focused question batches.
3. Resolve contradictions and critical implementation details.
4. Recommend and confirm architecture decisions.
5. Present a concise baseline for explicit approval.
6. Generate and self-check the complete YAML handoff.

## Boundaries

This is a requirements-engineering skill. It does not build or deploy Power Platform artifacts, generate app source, emit Power Fx or flow JSON, inspect a tenant without a connected tool, or claim that implementation has started.

The skill includes no executable scripts and makes no external service calls. Its references and YAML template are loaded only as needed.

## Add to Copilot Studio

In the Copilot Studio new agent experience, open an agent and select **Build > Skills > Add skill > Upload a skill**. Upload the bundle generated by the CAT Agent Skills gallery. After the skill is added, test its triggering and interview behavior in the agent preview.

Microsoft documentation: [Add an existing skill to an agent](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/skills-add-existing)

## Validation

The release was forward-tested in seven independent scenarios covering incomplete ideas, approved solutions, tenant blockers, contradictions, large solutions, direct build requests, and attempted approval with missing implementation-critical values.

All final scenarios passed structural, traceability, approval, readiness, dependency, build-order, and safe-YAML checks. A live Copilot Studio tenant import remains the final environment-specific smoke test.
