# Proposal response

## Production order
1. Host/user/brand/template authority takes precedence. Complete any required host design selection without inventing its result or bypassing hooks or permissions. A governing template or existing layout stays on the host's template-edit path; apply narrative and evidence without requiring fresh PptxGenJS creation. When the host authorizes original composition, read [design-to-production](references/custom-design-authoring.md) alone through EOF. Preserve supplied identity, palette, fonts and assets; fill only permitted choices. Write a concrete `design-language.md` in the actual active workspace, wait for successful Write, then issue a separate complete Read of that file before planning, outlining or authoring. A brand kit alone is not a governing template; its strictness and host restrictions determine the permitted choices.
2. Resolve paths from the successful Skill response's base directory, not a hardcoded harness directory. Read the host's resolved `image/SKILL.md` and `pptx/pptxgenjs-icons.md` separately, using the available skill roots for Claude or GHCP. Plan relevant image AND named semantic-icon slots in one measured permitted batch. Join results, retain actual paths; host/no-image/no-icon/no-notes limits prevail. Missing permission or unavailable guidance is a real blocker, not permission to fabricate assets or a design result.
3. For fresh PptxGenJS creation, require [production guard](scripts/production.cjs) in the ordinary build BEFORE adding slides. It validates your plan, not designs it: guard=production(pptx,{tokens:{colors:{...},fonts:{...}},slots:[{id,type:'image'|'icon',role}]},[{id,success:true,path:absoluteAssetPath}]). Use guard.place(id,slide,{x,y,w,h}) for each returned image/icon; export with guarded pptx.writeFile. Save guard.seal() to production-evidence.json. Missing/unplaced roles refuse export; fix actual assets, never dummyfiles. Explicit user/host exclusions may use exemptions:[{type,authority,reason}] and remain exceptions. Template editing follows host tools; verify equivalent placement, never replace brand layout.
4. Render every page; inspect source truth, meaningful relationships, readable lookup and actualmedia. No helper certifies aesthetic/semantic quality. Save `output.pptx` in the host's designated output directory and complete its normal delivery workflow; a local file is not delivery.

## Narrative and evidence
Determine customer/evaluators, request/version/addenda, audience, due date and format. Explicit buyer-facing request wins; source drafts do not authorize internal authoring instructions in customer slides. Keep truthful draft/approval limits without repeating internal bid-routing directions. Default12slides total: cover; response/conditions; priorities; coverage; solution/scope; delivery; proof/limits; milestones/parties; commercials; exceptions; clarifications; nextstep. User count/order and mandated response structure win; expand readable lookup, omit unsupported filler.
Build a typed source requirement ledger FIRST: ID, actual supplier response/state, evidence and material limit. Native register retains every mandatory answer/repetition; summary derives exact states, not an invented fully-supported count. Conditional supported entries remain conditional. Buyer requirement/allowance is not supplier capability/permission. Source wordings such as partiallyvalidated/pendingUAT cannot become validated. Never claim submission/approval/award without evidence; use preparedby, draftresponse, submissiondue.
Keep source currency/unit/period/scope, validity, inclusions/exclusions, optional/unpriced items and payment triggers. Reconcile totals. Preserve full global acceptance conjunctions; do not distribute them into invented phase gates. Dates: sourceweek n from kickoff+(n-1)*7 through kickoff+n*7-1; label assumption and preserve buyer target separately. Inputs/approval/acceptance each retain own date. Proof needs context/period/metric and authorized anonymity; no inventedROI or guaranteed outcomes. Keep included scope, exclusions and open conditions in separate groups. An unresolved approval is not excluded scope. New timing constraints remain proposed. End with suppliedowner/date or gaps, not authoring instructions.

## Focal exhibit choices
Use an editable requirement->solution->evidence map for supported relationships; order alone is not dependency. Phased delivery with start/end periods suits Gantt lanes, exact milestones get distinct symbols and buyer inputs stay bound to their own dates. A three-level solution pyramid needs real containment/priority, not invented capability rank. Commercial additive scope can use a reconciled cost waterfall with optional/unpriced scope separate. Mandatory response tables remain native indexed lookup; summary and close explain implications instead of repeating all rows.

Apply [final evidence and closure](references/final-evidence-check.md) to actual titles, labels, dates, edges and actions. Preserve complete readable lookup and source qualifications.

Use [response table allocation](references/decision-space.md) for complete required answers and [worked examples](references/worked-examples.md) for the production guard's structural contract, not as proof of presentation quality.
