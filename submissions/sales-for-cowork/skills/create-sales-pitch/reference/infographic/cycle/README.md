# Recurring arrow loops

Assets: `create-sales-pitch/reference/infographic/cycle/arrow-loop-3.pptx`,
`create-sales-pitch/reference/infographic/cycle/arrow-loop-4.pptx`,
`create-sales-pitch/reference/infographic/cycle/arrow-loop-5.pptx`,
`create-sales-pitch/reference/infographic/cycle/arrow-loop-6.pptx`.

- **Use:** actual recurring stages with a final-to-first return. Choose the matching
  cardinality; arc area is not time, money or effort.
- **Adapt:** stage titles plus useful descriptions, including outside the ring;
  reflow text boxes, enlarge text independently, and reposition matching icons.
  Uniformly scale/translate the ring while fitting the explanation to the page.
- **Preserve:** arrow custom paths/transforms, topology, arrowheads, gaps, center
  and return meaning. Protect arrows, not every label anchor or whole-group
  position. Never delete an arc, invent a stage or stretch a one-time process
  into a loop.
  An explicitly requested curved closed cycle needs a curved directed return,
  whether adapted or originally authored. Generic boxes and disconnected arrows
  are not an equivalent; move explanations outside rather than discard the ring.
- **Data/media:** use `cycle_stages` in `../manifest.json` for source-order
  label/icon pairing, not shape enumeration or visual quadrant order.
  The five-stage ring and legend repeat each concept but can need different ink.
  Transparent sourced icons sit on the actual backdrop without decorative white
  backing tiles. Keep the necessary white center and arrow gaps.

`CYCLE_STAGE_*_DESCRIPTION`, `CYCLE_CENTER` and `ICON_CYCLE_STAGE_*` are editable
roles. Inspect every stage/icon/description in order and back to the start.
An explicit no-icon request removes icons, not the required return geometry.
Use a clearly labeled native loop. Unsupported
counts need an honest native return graph, not a mutilated donor. One-time order
belongs in Timeline; peers belong in List. Source and arrow geometry identities
are in `../manifest.json`.
