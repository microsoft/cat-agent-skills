# Pipeline review

## Production order
1. Host/user/brand/template authority takes precedence. Complete any required host design selection without inventing its result or bypassing hooks or permissions. A governing template or existing layout stays on the host's template-edit path; apply narrative and evidence without requiring fresh PptxGenJS creation. When the host authorizes original composition, read [design-to-production](references/custom-design-authoring.md) alone through EOF. Preserve supplied identity, palette, fonts and assets; fill only permitted choices. Write a concrete `design-language.md` in the actual active workspace, wait for successful Write, then issue a separate complete Read of that file before planning, outlining or authoring. A brand kit alone is not a governing template; its strictness and host restrictions determine the permitted choices.
2. Resolve paths from the successful Skill response's base directory, not a hardcoded harness directory. Read the host's resolved `image/SKILL.md` and `pptx/pptxgenjs-icons.md` separately, using the available skill roots for Claude or GHCP. Plan relevant image AND named semantic-icon slots in one measured permitted batch. Join results, retain actual paths; host/no-image/no-icon/no-notes limits prevail. Missing permission or unavailable guidance is a real blocker, not permission to fabricate assets or a design result.
3. For fresh PptxGenJS creation, require [production guard](scripts/production.cjs) in the ordinary build BEFORE adding slides. It validates your plan, not designs it: guard=production(pptx,{tokens:{colors:{...},fonts:{...}},slots:[{id,type:'image'|'icon',role}]},[{id,success:true,path:absoluteAssetPath}]). Use guard.place(id,slide,{x,y,w,h}) for each returned image/icon; export with guarded pptx.writeFile. Save guard.seal() to production-evidence.json. Missing/unplaced roles refuse export; fix actual assets, never dummyfiles. Explicit user/host exclusions may use exemptions:[{type,authority,reason}] and remain exceptions. Template editing follows host tools; verify equivalent placement, never replace brand layout.
4. Render every page; inspect source truth, meaningful relationships, readable lookup and actualmedia. No helper certifies aesthetic/semantic quality. Save `output.pptx` in the host's designated output directory and complete its normal delivery workflow; a local file is not delivery.

## Narrative and evidence
Establish team/horizon/cutoff/currency/target and selected IDs. Default9slides total: cover; forecast/gap; scenarios; movement; exposure; priorities; support; actions; decisions. Add readable appendix pages as needed. Quiet-week shortening requires stable evidence; user structure wins. Main pages select manager interventions, not every CRM row.
FIRST create a typed source ledger keyed byID with amount, stage, seller category, blocker, FULL next action, action owner/date and target close. Generate separate native Action-register pages from ID/action/owner/date tuples; never squeeze these into the wide roster. Paginate for comfortable type. Never omit it because the roster already lists blockers/dates, or substitute an ID-only calendar. Summaries link to this complete register. Verify source action tuples against visible native rows; no notes-only coverage.
Compute rollups/counts/scenarios from the same IDs, and insert computed values into labels. Changed-ID union plus unchanged complement equals the population. Snapshot endpoints cannot prove skipped intermediate stages. Explicit before/after membership prevents losing Best case while comparing an upside scenario. Stage, category and probability differ; no category is uncategorized unless source says so. Closed-won appears once in cumulative scenarios, not in open totals. Weighting requires supplied probabilities. Partial same-ID snapshots cannot prove full won/lost/creation movement. Keep new-ARR/creation exclusions, period and denominator beside measures. CRM hygiene is not close proof. Overdue uses cutoff/rule; full action semantics survive.
Manager choices and routine follow-up differ. Additions to owner/date, downgrade destination or acceleration are labeled proposed; creating a deck does not editCRM or submitforecast. Each opening gap reaches a sourced action or explicit question.

## Focal exhibit choices
Movement waterfall needs the same complete population and opening+signed changes=closing; same-ID snapshots cannot prove wins/loss/additions. Forecast uses separate cumulative bands with closed-won included once and a target marker, never a stacked overlap. For close/action timing, use a Gantt only with actual start/end spans; deadline-only records use milestones on shared calendar lanes. Priorities can form a labeled three-level pyramid when ordering is sourced or explicitly proposed; tier area is not deal value or conversion. Bind selected deal->blocker->intervention->owner/date with native connectors; full roster remains readable lookup.

Apply [final evidence and closure](references/final-evidence-check.md) to actual titles, labels, dates, edges and actions. Preserve complete readable lookup and source qualifications.

Use [discussion and action lookup](references/decision-space.md) to allocate readable action homes and [worked examples](references/worked-examples.md) for the production guard's structural contract, not as proof of presentation quality.
