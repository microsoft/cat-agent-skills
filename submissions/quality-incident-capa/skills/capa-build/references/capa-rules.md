# CAPA Rules (cited as capa-rules.md #<n>; constants in engines mirror these sections)
## 1. Containment first
No CA/PA work is complete without documented containment of the nonconforming material/process.
## 2. Root cause discipline
2.1 Root cause must come from a structured method (Pareto -> 5-Why chain) over the complaint window, not the incident narrative.
2.2 The why-chain must terminate at a process/system cause, minimum depth 3.
## 3. Cause-category constraints
3.4 "Operator error" is NOT acceptable as a terminal root cause when the same defect category recurs (recurrence > 1) across parts, machines, or shifts - the 5-Why must go deeper (training system, fixture, calibration, standard work). Reject and escalate.
## 4. Effectiveness checks
Every corrective AND preventive action requires an effectiveness check: metric, owner, verification window (days). Missing any field blocks closure.
## 5. Systemic scope
A systemic root cause (>= 2 parts or >= 2 machines affected) REQUIRES a preventive action covering the full affected scope, not just the triggering part.
## 6. Closure readiness
Closure requires: containment present (#1), verified root cause (#2), CA + (PA if systemic #5), all effectiveness checks complete per #4, verification evidence planned. Anything missing is a named blocker.
## 7. Confidence floor
Root-cause confidence < 0.75 blocks closure and routes to quality-manager review.
