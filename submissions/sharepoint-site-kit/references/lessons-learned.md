# Lessons learned

From building a real program site with a branded HTML landing page (one week, about ten iterations). Each lesson names the rule it produced in SKILL.md.

| # | What happened | Rule |
|---|---|---|
| 1 | The agent assumed HTML files in Site Pages download instead of rendering and built a standard .aspx page. The user wanted an HTML page. | Ask the page mode up front: static HTML, live list-backed HTML, or standard page. Never pick silently. |
| 2 | Publishing failed with "Could not publish your page... unexpected error". Tenant-wide settings (Microsoft 365 baseline security mode, for example "Block creation and editing of classic SharePoint pages" or "Don't allow new custom scripts") can block HTML pages. Files uploaded through the file API can be treated differently from pages added through the UI. | Run one publish probe early. If blocked, deliver the file with the supported path (Pages > Create or upload > Upload HTML page, then Publish page) and an admin note naming those settings (Microsoft 365 admin center: Settings > Org settings > Security and privacy). Never work around a policy. |
| 3 | The agent could not overwrite a file in Site Pages, so every edit made a new draft. Five leftovers piled up. | Batch all changes and upload once per approval round, under one stable name (`<Page-Name>.html`, never `-preview`). Test overwrite in the probe. List leftovers for the user to delete; the agent cannot delete files. |
| 4 | Folder links pointing at the folder URL opened the top of the Documents library. | Build links to the library view with the URL-encoded server-relative folder path: `.../Shared%20Documents/Forms/AllItems.aspx?id=%2Fsites%2F<site>%2FShared%20Documents%2F<Folder>`. Click-test every link in a browser before handover. |
| 5 | A folder was renamed (Kickstarter to Activate) and its card broke. | Upkeep diffs page links against library folders, fixes only what changed, asks the user to confirm renames, and reports folders with no card (asking for a lead and a one-line description). |
| 6 | Leads were guessed from documents. | Fill leads from the library's Lead column only. If empty, show "Lead to be confirmed". Never invent. |
| 7 | Users rejected generic logos and a star icon. They accepted an icon made from the page header colors and shapes. | Generate the site icon from the page palette and hero motif, padded for SharePoint's round crop, 512 and 256 px. Setting it is manual: Settings (gear) > Change the look > Header > Site logo > Change. |
| 8 | The agent could not set folder colors. | Give the manual step: right-click the folder > Folder color. |
| 9 | A workstream name contained "/", which folder names cannot hold. | Sanitize names (`build_folder_links.py sanitize`) and report every rename. |
| 10 | First headlines described the team format ("Six teams, one per stream") instead of what the program does. | Derive headlines from the program's own source documents and offer 2 or 3 alternatives. Write outcome-led h2s. |
| 11 | The new page looked like a sibling site's page, and people mixed them up. | Ask for sibling sites and choose a visibly different accent, hero motif or layout. |
| 12 | Session lengths like "12 min" looked odd. | Round durations up to 5, 10, 15, 20, 30, 45 or 60 minutes. |
| 13 | The user wanted the first page the kit built to open as the site's home page, not only sit in Site Pages. | Confirm at intake that the first page becomes the home page (with an opt-out), record the old home page (for example Home.aspx) so it can be restored, and keep it, never delete it. Set it with SharePoint's Make homepage command (Site Pages > select the page > ... (More) > Make homepage): browser first, SharePoint REST `rootfolder` `WelcomePage` second (Graph v1.0 has no endpoint), manual clicks last. |
| 14 | The agent cannot always overwrite files in Site Pages, so new versions can get numbered file names, and publishing can be blocked by tenant settings. A home page that is not published can show visitors a draft or an access error. | Order: build the preview, user review, publish (or the user publishes through Pages > Create or upload > Upload HTML page), then Make homepage, then load the site root to confirm. Each new version has a new file name, so upkeep reruns Make homepage on the new file. UNVERIFIED: whether Make homepage is offered for `.html` pages and whether it works on a draft. Fallback: keep the old home page and add a prominent link or hero button to the HTML page. Not yet tested on a live site. |
| 15 | Pages copied two skewed rounded tiles from a reference page, and they read as the Cowork product logo. | Keep the decoration generic (orbs, arcs, dot grid, or an image the user supplied). Never draw shapes or gradients that echo a product logo. |
